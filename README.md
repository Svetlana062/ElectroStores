# ElectroStores
Платформа для управления сетью магазинов электроники

## Описание:
Платформа для управления торговой сетью электроники с иерархической структурой
(заводы, розничные сети, ИП). Каждое звено сети ссылается только на одного
поставщика оборудования (не обязательно предыдущего по иерархии). Важно отметить,
что уровень иерархии определяется не названием звена, а отношением к остальным
элементам сети, т.е. завод всегда находится на уровне 0, а если розничная сеть
относится напрямую к заводу, минуя остальные звенья, ее уровень — 1.

### Основные возможности:
* Иерархическая структура сети: Управление узлами (заводы, сети, ИП) с
автоматическим расчетом уровней иерархии. Каждый узел связан с одним поставщиком.
* CRUD-операции: Полный набор операций (создание, чтение, обновление, удаление)
для узлов и продуктов через REST API.
* Фильтры и поиск: Фильтрация узлов по стране (например, ?country=Russia), поиск по
имени или городу. Сортировка по имени или дате создания.
* Пагинация: Разбиение результатов на страницы (по умолчанию 10 элементов, максимум 100).
* Аутентификация и права доступа: Только активные сотрудники (с флагом is_staff=True)
могут взаимодействовать с API. Поддержка сессионной, токеновой и базовой аутентификации.
* Админ-панель: Веб-интерфейс для управления данными (узлы, продукты) через Django Admin.
* Продукты: Many-to-Many связь с узлами, позволяющая привязывать продукты к
нескольким узлам сети.

### Требования к окружению
* Python 3.13+
* Poetry для управления зависимостями
* PostgreSQL 10+ (рекомендуется) или SQLite
* DRF 3.14+

## Установка и запуск локально

1. Клонируйте репозиторий:
    ```bash
    git clone https://github.com/Svetlana062/ElectroStores.git
    ```

2. Активируйте виртуальное окружение (рекомендуется использовать Poetry):
    ```bash
    poetry shell
    ```

3. Установите зависимости:
    ```bash
    poetry install
    ```

4. Создайте файл `.env` на основе `.env.example` и заполните необходимые переменные окружения.

5. Выполните миграции базы данных:
    ```bash
    python manage.py migrate
    ```

6. Запустите сервер разработки:
    ```bash
    python manage.py runserver
    ```

Сервер будет доступен по адресу: http://localhost:8000/

## Использование
* Админ-панель: `/admin/` (для управления узлами и продуктами).
* API: `/api/nodes/` (CRUD для узлов), `/api/products/` (CRUD для продуктов).
Фильтры: по стране (`?country=Russia`), поиск по имени/городу.
* Права: Только активные сотрудники (is_staff=True).

## Структура проекта
Проект построен на Django с использованием Django REST Framework (DRF) для API.

Основные компоненты:
* Модели узлов и продуктов с иерархической структурой и связями (network/models.py);
* Миграции базы данных (network/migrations/);
* Сериализаторы API для узлов и продуктов (network/serializers.py);
* ViewSet'ы для CRUD-операций с фильтрами и пагинацией (network/views.py);
* Разграничение прав доступа для активных сотрудников (network/permissions.py);
* Настройки пагинации (network/pagination.py);
* Регистрация моделей в админ-панели (network/admin.py);
* Маршруты API (network/urls.py);
* Тесты для моделей, сериализаторов и API (network/tests.py);
* Основные настройки проекта (config/settings.py);
* Корневые маршруты (config/urls.py).

## Тестирование
Покрытие тестами — 95% (проверено с помощью coverage.py). Тесты покрывают:
* Модели (валидация данных, связи).
* Сериализаторы (корректность преобразования).
* ViewSet'ы (CRUD-операции, фильтры, пагинация).
* Аутентификацию и права доступа (401/403 ошибки).
* Интеграционные тесты API.

### Запуск тестов:
1. Установите coverage (если не установлено): poetry add coverage.
2. Запустите тесты с покрытием:
   ```bash
   coverage run manage.py test
   coverage report
   ```
   Если тесты падают, проверьте настройки БД и переменные окружения в .env.
